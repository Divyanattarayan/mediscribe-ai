### Requirement: A structured clinical representation precedes generation
<!-- id: clinical_extraction.extract_clinical_representation -->
<!-- entities: Transcription, MedicalEntity -->
<!-- enforced: clinical_extraction.extract_clinical_representation() -->
<!-- triggers: A SOAP note is generated by the LLM with a rule-based fallback -->

Stage 4 SHALL build a normalised intermediate representation from the transcript
and categorised entities before generation, preferring an LLM extraction and
always falling back to local heuristics so the pipeline keeps working without
network access. Both paths SHALL pass through `_postprocess_representation`.

#### Scenario: the model is available
- **WHEN** `_extract_with_groq` succeeds
- **THEN** the structured result is post-processed and returned

#### Scenario: the model is unavailable
- **WHEN** `_extract_with_groq` raises for any reason
- **THEN** `_extract_with_rules` produces the representation and the same
  post-processing applies — no exception escapes

#### Scenario: entities are split by assertion
- **WHEN** entities are compacted into the representation
- **THEN** `_split_by_assertion` uses `is_active_patient_finding` so denied,
  historical, hypothetical and family mentions are not listed as active problems

### Requirement: A SOAP note is generated by the LLM with a rule-based fallback
<!-- id: soap_generator.generate_soap_note -->
<!-- entities: SoapNote, Transcription, ClinicalFact -->
<!-- enforced: soap_generator.generate_soap_note(), soap_generator._generate_with_groq(), soap_generator._generate_fallback() -->
<!-- depends_on: A structured clinical representation precedes generation -->

`generate_soap_note` SHALL attempt LLM generation first and, on any failure —
network, key, malformed JSON, or a response missing any of the four required
keys — SHALL fall back to rule-based generation. Both paths SHALL produce a dict
with `subjective`, `objective`, `assessment`, `plan`, `generated_at`, `source`
and `resolved_style_profile`, and both SHALL pass through validation and repair.

#### Scenario: the LLM path succeeds
- **WHEN** the model returns valid JSON containing all four section keys
- **THEN** `source` is `f"groq-{GROQ_MODEL}"`

#### Scenario: the LLM response is missing a section
- **WHEN** the parsed JSON lacks one of subjective/objective/assessment/plan
- **THEN** `_generate_with_groq` raises `ValueError` and the fallback runs with
  `source = "rule-based-fallback"`

#### Scenario: section shapes vary by path
<!-- test: tests/test_soap_sections.py::test_every_section_is_a_string_after_normalising -->
- **WHEN** a section value is a dict, a list, None or an empty string
- **THEN** `_normalize_soap_sections` renders it to prose, unwraps a lone `note`
  key, comma-joins lists, and substitutes `INSUFFICIENT_SECTION_TEXT` for empty
  values

#### Scenario: prose is untouched
<!-- test: tests/test_soap_sections.py::test_prose_passes_through_untouched -->
- **WHEN** a section is already a prose string
- **THEN** it passes through unchanged

#### Scenario: a dict never reaches the user as a Python repr
<!-- test: tests/test_soap_sections.py::test_dict_becomes_prose_not_a_python_repr -->
- **WHEN** the fallback path emits a structured dict section
- **THEN** it is flattened to labelled prose

### Requirement: The generation prompt is led by the fact table
<!-- id: soap_generator._generate_with_groq -->
<!-- entities: ClinicalFact, SoapNote -->
<!-- enforced: soap_generator._generate_with_groq() -->
<!-- depends_on: A SOAP note is generated by the LLM with a rule-based fallback -->

When a fact table is supplied, the user message SHALL open with the rendered
assertable facts, instructing the model to prefer them over its own reading and
to honour the grouping exactly. The raw transcript SHALL still follow, so the
model can phrase naturally and catch what extraction missed — constraining it to
the table alone would trade hallucination for omission.

#### Scenario: a fact table is present
- **WHEN** `fact_table` is non-empty
- **THEN** `render_for_prompt` output precedes the transcript in the user message

#### Scenario: no fact table
- **WHEN** `fact_table` is empty or None
- **THEN** the prompt contains transcript, metadata, representation, style and
  entity summary only

### Requirement: The note is scored and repaired accept-if-better
<!-- id: soap_generator._validate_and_repair_soap_note -->
<!-- entities: SoapNote, VerificationReport -->
<!-- enforced: soap_generator._validate_and_repair_soap_note(), soap_generator._score_soap_quality() -->
<!-- depends_on: A SOAP note is generated by the LLM with a rule-based fallback -->

Claim verification SHALL run before any repair. The note SHALL then be scored
out of 100 across weighted sections (subjective 25, objective 20, assessment 30,
plan 25) with penalties per issue — unsupported_claims 15 being the heaviest,
above the ungrounded_terms 12 lexical proxy it replaced. Below the
`_QUALITY_PASS_THRESHOLD` of 85.0, deterministic rule repair is tried, then LLM
section regeneration. Each stage SHALL be kept only when it scores at least as
well as what it replaced, judged the same way.

#### Scenario: the note already passes
- **WHEN** the overall score is at or above 85.0
- **THEN** neither repair nor regeneration runs

#### Scenario: rule repair does not improve the score
- **WHEN** the repaired note scores lower than the original
- **THEN** the original is kept

#### Scenario: regeneration changed no prose
- **WHEN** regeneration returns text identical to the current note
- **THEN** the previous verification is reused rather than paying for a second
  verification call

#### Scenario: regeneration changed prose
- **WHEN** any section differs after regeneration
- **THEN** the regenerated note is re-verified afresh before being scored

#### Scenario: a section the transcript cannot support
- **WHEN** a section equals `INSUFFICIENT_SECTION_TEXT`
- **THEN** `_regenerate_weak_sections` leaves the placeholder alone

#### Scenario: LLM section regeneration fails
- **WHEN** `_regenerate_section_with_groq` raises
- **THEN** `_regenerate_section_with_rules` supplies the section instead

### Requirement: The quality report states what groundedness check actually ran
<!-- id: soap_generator._score_soap_quality -->
<!-- entities: SoapNote, VerificationReport -->
<!-- enforced: soap_generator._score_soap_quality() -->

The report SHALL carry `groundedness_check` set to `claim_entailment` when
verification ran and `lexical_terms` otherwise, so a score can be read for what
it actually checked. A verifier that did not run SHALL be printed out loud.

#### Scenario: verification ran
- **WHEN** `verification.ran` is true
- **THEN** `groundedness_check` is `claim_entailment`

#### Scenario: verification did not run
- **WHEN** the verifier could not run
- **THEN** `groundedness_check` is `lexical_terms` and the degradation is logged

### Requirement: Documentation style is resolved from user defaults plus request overrides
<!-- id: documentation_style.resolve_style_profile -->
<!-- entities: User, SoapNote -->
<!-- enforced: documentation_style.resolve_style_profile(), documentation_style.serialize_style_profile() -->

The style profile SHALL be the user's stored preferences, layered with any
non-None per-request overrides. Invalid values SHALL normalise to defaults
rather than raise: unknown presets to `balanced`, unknown focus to `general`,
unknown encounter type to `follow_up`.

#### Scenario: known values pass through

- **WHEN** the value is in the allowed set
- **THEN** it is returned unchanged

#### Scenario: unknown values normalise
<!-- test: tests/test_documentation_style.py::test_unknown_presets_fall_back_to_default -->
- **WHEN** the value is not recognised
- **THEN** the default is substituted

#### Scenario: an unknown encounter type
<!-- test: tests/test_documentation_style.py::test_unknown_encounter_type_falls_back_to_follow_up -->
- **WHEN** `encounter_type` is outside the four known types
- **THEN** it resolves to `follow_up`

#### Scenario: overrides layer over user defaults
<!-- test: tests/test_documentation_style.py::test_overrides_layer_over_user_defaults -->
- **WHEN** a request supplies a subset of style fields
- **THEN** those override the user's stored values and the rest are inherited

#### Scenario: None-valued overrides are inert

#### Scenario: bulleted plan

### Requirement: The note and its entities are persisted in one transaction
<!-- id: main.transcribe_audio_endpoint -->
<!-- entities: Transcription, MedicalEntity, SoapNote, User -->
<!-- enforced: main.transcribe_audio_endpoint() -->

Stage 7 SHALL flush the `Transcription` row to obtain its id, add every entity
row and exactly one `SoapNote` row, and commit once. Section values SHALL be
coerced to strings before persistence, since LLM sections are strings and
fallback sections are dicts.

#### Scenario: a successful run
<!-- test: tests/test_transcribe_flow.py::test_successful_transcribe_persists_a_row -->
- **WHEN** the pipeline completes
- **THEN** one transcription, its entities and one soap note exist, linked to
  the authenticated user, with `status="complete"`

### Invariant: A note is always returned
<!-- entities: SoapNote -->
<!-- enforced: soap_generator.generate_soap_note() -->

Whatever fails — the model, the network, the JSON, the repair — the pipeline
SHALL receive a valid SOAP dict with all four sections as strings. The `source`
field SHALL always say which path produced it.

### Invariant: Unsupported claims are named, never silently rewritten
<!-- entities: SoapNote, ClaimVerification -->
<!-- enforced: soap_generator._validate_and_repair_soap_note(), claim_verification.verify_note() -->

The repair path SHALL hand a weak section back to the generator with its
specific issues named. A regex-driven layer that deletes matching sentences —
which silently dropped true findings — SHALL NOT be reintroduced.
